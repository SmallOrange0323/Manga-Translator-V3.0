# 本地大量圖片翻譯修正（2026-10-14）

使用者回報：本地選取 170 張圖片後，按紫色「翻譯所選」仍停留在選圖畫面。

## 問題與修正

原側邊欄將所有圖片的 data URL 一次傳給背景，沒有捕捉傳送錯誤。Chrome 的單則擴充套件訊息上限為 64 MiB；大量本地圖片會超出上限。使用 170 張、合計約 85 MiB 的合成資料，已在依官方訊息上限建立的模擬環境重現相同失敗。尚未直接讀取使用者 Chrome 的錯誤日誌，不能斷言其實際圖片的總大小。

官方依據：https://developer.chrome.com/docs/extensions/develop/concepts/messaging

- 本地圖片每段最多 2 MiB，依順序傳送，所有圖片完整接收後才開啟結果頁。
- 傳送時按鈕顯示進度並防止重複提交；失敗時顯示原因並保留選图。
- 本地任務不再依賴目前的網頁分頁，也不因網頁切換或關閉而失效。
- 背景在結果頁確實建立後才回報啟動成功；啟動失敗會清除該次建立的空白分頁。
- 結果頁使用小型譯文快照與分段圖片訊息，防止已完成圖片累積後再次超過訊息上限。每個結果頁的訊息依序發送，過期任務與版本的圖片片段不會套用。
- 僅傳送新完成／更新的圖片；完成狀態不重送整本圖片。重新載入結果頁時，可從目前仍存活的背景記憶體重新接收圖片。
- 本地圖片保留實際檔名，避免顯示 base64 尾碼。
- 圖片內容仍僅暫存在記憶體；持久化任務與譯文遵循既有 storage-first 機制。背景重啟後，尚未完成的本地圖片需重新選取，傳送失敗可按翻譯重試。

## 驗證

- 37 個測試檔案、502 項測試通過。
- 170 張超過 64 MiB 的合成資料經實際側邊欄點擊程式與分段傳送流程完整接收；各則訊息低於 3 MiB。
- 驗證單張跨多段、頁序、精確內容、失敗保留選圖、重複點擊防護、過期／不完整傳送、啟動失敗回報與空白分頁清理。
- 驗證大量圖片的結果更新、結果頁重新載入、舊片段拒絕、狀態更新順序，以及圖片不寫入 chrome.storage.local。
- 未呼叫真實付費翻譯 API；仍需在使用者 Chrome 實機確認。

## 使用

原本從本專案 dist-v3 載入的擴充套件：在 chrome://extensions 按「重新載入」，關閉再重開側邊欄，重新選取圖片。

測試 ZIP 可解壓縮後以「載入未封裝項目」安裝。優先重新載入原擴充套件，以保留原本的設定與 API 金鑰。
